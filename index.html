MergePik 개인정보처리방침

시행일: 2026년 10월 5일

MergePik(이하 "앱")은 사용자가 고른 폴더의 사진 · 동영상을 기기 안에서 분석해 비슷한 사진을 묶고, 분류하고, 정리하는 안드로이드 앱이다. 이 방침은 앱이 어떤 정보를 다루고, 어디에 두고, 언제 기기 밖으로 보내는지 적는다.

요약

  • 개발자는 사용자의 정보를 모으지 않는다. 개발자의 서버가 없고, 분석 · 광고 · 오류 보고 도구(SDK)를 넣지 않았다. 계정도 없다.
  • 사진의 분석 · 묶음 · 분류 · 학습은 기기 안에서 한다. 사용자가 Claude 를 켜면 Claude 가 분류를 돕는다(3).
  • 사진이 기기 밖으로 나가는 길은 하나뿐이다. 사용자가 설정에서 Claude 를 켜고 안내에 동의하고 자신의 Anthropic API 키를 넣은 뒤, 사용자가 묻거나 켠 자동 설정에 따라 긴 변 512px 이하로 새로 만든 JPEG(위치 · 기기 · 촬영 시각 정보 없음)을 Anthropic 으로 보낸다.
  • Claude 는 처음에 꺼져 있다. 꺼져 있으면 앱은 네트워크를 전혀 쓰지 않는다.

1. 기기 안에서 다루는 정보

아래 정보는 기기의 앱 전용 저장공간에 둔다. 개발자에게 보내지 않는다.

  • 고른 폴더: 접근 권한, 폴더 이름 · 경로. 폴더를 다시 열 때 쓴다.
  • 파일 목록: 이름, 확장자, 하위 폴더 경로, 크기, 해상도, 촬영 · 수정 시각, 동영상 길이, 기기의 미디어 번호(MediaStore ID). 홈의 개수 · 용량 · 기간과 정렬에 쓴다. 폴더를 다시 읽을 때 폴더와 맞춘다.
  • 분석 결과: 사진마다 계산한 숫자 벡터(그림의 특징), 선명도 · 노출 · 구도 · 픽셀 해시, 얼굴의 자리 · 크기 · 검출 점수와 얼굴 부분의 선명도, 눈 뜸 · 미소 점수. 비슷한 사진 묶기, 1등 고르기, 분류에 쓴다.
  • 이웃 목록: 폴더마다 분석 결과의 사본(사진의 열쇠, 벡터, 파일 크기 · 해상도 · 촬영 시각 등)과 비슷한 사진 후보를 담은 파일. 폴더 선택 창으로만 읽은 사진의 열쇠에는 문서 경로 · 이름이 든다. 폴더를 다시 빨리 열 때 쓴다. 백업 · 기기 간 이전에 들지 않고, 하루 한 번 치울 때 최근에 연 폴더 5곳의 것만 남긴다.
  • 학습: 사용자가 바꾼 분류(그 사진의 벡터 사본과 함께), Claude 의 답, 직접 정한 1등, 묶음에서 뺀 사진 쌍, 1등 일치율 기록. 분류와 1등을 사용자에게 맞추는 데 쓴다.
  • 작업 기록: 휴지통으로 보내기 · 복원 · 영구 삭제, 폴더로 정리와 그 되돌리기의 대상(파일 이름 · 경로 포함)과 결과. 실행 취소와 중단된 작업의 정리에 쓴다.
  • Claude 기록: 보낼 차례를 기다리는 사진, Claude 가 거절했거나 보내지 못한 사진, 분류를 되돌려 자동으로 다시 보내지 않을 사진, 날짜 · 폴더 · 모델별 토큰 수와 추정 비용, 보내기를 멈추게 한 응답의 한 줄(상태 · 오류 종류 · API 의 말 · 요청 ID). 사용량 · 월 한도를 보이고, 같은 사진을 자동으로 다시 보내지 않는 데 쓴다.
  • 작업 중 표시: 분석하거나 파일 정보를 읽는 동안 앱이 멈추는 파일을 다시 열지 않으려고, 지금 여는 파일을 적어 두는 작은 파일. 분석의 표시에는 여는 파일의 열쇠(기기의 미디어 번호, 폴더 선택 창으로만 읽은 사진은 문서 경로 · 이름)와 크기 · 수정 시각이 든다. 정보 읽기의 표시는 파일을 해시로만 가리킨다(이름 · 경로가 없다). 앱 전용 저장공간에 있고 일이 끝나면 지운다(앱이 멈췄으면 다음에 그 일이 끝날 때).
  • 설정: 앱의 설정과 화면이 기억하는 작은 값(게이지 칸, 그리드 칸 수, 화면 모드 등).

얼굴 · 위치 정보 · 모델 · 로그는 이렇게 다룬다.

  • 얼굴은 있는지, 자리 · 크기와 선명도, 눈을 떴는지 · 웃는지만 잰다. 누구인지 알아보지 않는다(얼굴을 사람마다 가르거나 대조하지 않는다).
  • 사진의 위치 정보(GPS)는 읽지 않는다. 위치 권한도 없다.
  • 분석에 쓰는 모델(TinyCLIP, MediaPipe 얼굴 모델)은 앱에 들어 있고 기기에서 돈다.
  • 앱은 사진, 사진에서 뽑은 정보, API 키를 기기의 로그에 적지 않게 만들었다.

2. 개발자가 모으는 정보

없다. 앱은 개발자에게 아무것도 보내지 않는다.

Google Play 는 Google 의 정책에 따라 설치 수 같은 통계와, 사용자가 기기에서 허용한 경우의 비정상 종료 보고를 개발자에게 보여 줄 수 있다. 이것은 Google Play 가 하는 일이고 앱이 따로 보내는 것이 아니다.

3. Claude(선택 기능) — 기기 밖으로 나가는 사진

켜는 법. 설정 → 분류 엔진 · Claude → [Claude 사용]을 처음 켤 때 무엇을 보내는지 알리는 안내가 뜨고, [동의하고 켜기]를 눌러야 켜진다. 한 번 동의한 뒤에는 다시 켤 때 묻지 않는다. 다만 앱 업데이트로 안내의 뜻이 바뀌면 같은 안내로 한 번 다시 묻는다(켜 두었으면 설정의 "Claude 안내가 바뀌었다 — 다시 보고 동의" 줄의 [보기]나 [Claude 에게 묻기]를 누를 때, 꺼 두었으면 다시 켤 때). 다시 동의할 때까지는 사진을 보내지 않고 키 확인도 하지 않는다. 보내려고 기다리던 사진은 그대로 기다리다가 동의하면 보낸다. 보내려면 사용자가 Anthropic 콘솔에서 만든 자신의 API 키를 넣어야 한다.

보낼 때. [Claude 에게 묻기]나 표본 카드를 누를 때, 그리고 사용자가 켠 설정에 따라 — "헷갈리는 사진 자동" 을 켜거나 "Claude 중심" 을 고를 때와, 둘 중 하나가 켜져 있는 동안 분석이 끝날 때. 보내지 못하고 기다리던 사진은 연결이 돌아오거나, 키 확인이 맞거나, [다시 시도] · 월 한도 바꾸기 · 폴더로 정리가 끝난 뒤에 보낸다. 자동으로 보내는 것은 앱이 뒤에 있을 때(예: "충전 중에만" 분석이 끝난 뒤)도 돌고, 그때는 알림 없이 보낸다. 답이 형식에 맞지 않으면 한 번 더 묻고 거절되면 한 장씩 다시 묻기 때문에, 같은 사진이 두 번 이상 갈 수 있다.

보내는 사진.

  • [Claude 에게 묻기]: 사용자가 고른 사진. 직접 분류한 사진과 아직 분석하지 않은 사진은 빼고 보낸다.
  • 표본 카드: 폰 안 모델이 분류한 사진 중 많아야 50장(헷갈리는 사진부터).
  • "Claude 중심": 지금 폴더에서 직접 분류도 Claude 의 답도 없는 사진 모두("하위 폴더 포함" 을 끄면 하위 폴더의 사진은 빼고), 그리고 분석이 끝날 때마다 새 사진. 새로 보낼 사진이 200장을 넘으면 예상 토큰과 추정 비용을 보이고 먼저 묻는다.
  • "헷갈리는 사진 자동": 폰 안 모델이 분류했고 헷갈린다고 표시한 사진만. 한 번 거친 폴더에서는 그 뒤에 분석한 사진(다시 분석한 사진 포함)만 고른다 — 헷갈리는 사진 자동을 껐다 켜거나, 폴더를 해제했다 다시 받거나, 학습을 초기화해도 그렇다.
  • 분류를 되돌린 사진은 자동(표본 카드 · "Claude 중심" · "헷갈리는 사진 자동")으로 고르지 않는다. 사진 보기의 정보에서 [다시 허용]을 누르면 그 사진(같은 내용의 사본 포함)을 다시 자동으로 고를 수 있다.

보내는 것.

  • 사진을 긴 변 512px 이하로 줄여(더 작은 사진은 키우지 않는다) 새로 만든 JPEG. 원본 파일은 보내지 않는다. EXIF · XMP(위치 · 기기 · 촬영 시각 등)와 그 밖의 정보 조각은 들어가지 않고(JFIF 머리와 색 프로필만 남을 수 있다), 앱이 보내기 직전에 한 번 더 확인한다. 동영상은 가운데(50% 지점)에 가장 가까운 키 프레임 한 장(길이를 모르면 대표 프레임)을 같은 방식으로 만든다. 동영상 프레임은 긴 변 512px 에 맞춰 키울 수 있다.
  • 분류 지시문(다섯 분류의 설명), 사진 번호, 답의 형식(분류 키 · 확신도), 고른 모델 이름. Sonnet 5.5 · Opus 5.5 를 고르면 노력 설정과, 거절하면 Anthropic 이 다른 Claude 모델로 넘기는 설정도 함께 보낸다.
  • 요청의 자격 증명인 사용자의 API 키, 그리고 요청마다(키 확인 포함) 붙는 기술 머리글. Anthropic 의 공식 SDK 가 붙이는 것: SDK 자체의 User-Agent(SDK 이름과 판), 언어(Java), SDK 판, Kotlin 판, 런타임 이름과 판, 운영체제 이름(Android), 운영체제 판(빈 값 — SDK 는 커널 판 글자를 넣는데, 제조사에 따라 기기 모델 · 펌웨어 판이 들 수 있어 앱이 비워 보낸다), CPU 종류, 다시 보낸 횟수(늘 0), 요청 · 읽기의 시간 제한. 그리고 API 판과, Sonnet 5.5 · Opus 5.5 를 고르면 거절된 요청을 다른 Claude 모델로 넘기는 기능의 이름. 그 밖에는 HTTP 의 보통 머리글(받는 형식 · 압축 · 본문 길이 등)뿐이다.
  • 인터넷 연결이 늘 그렇듯 기기의 IP 주소가 Anthropic 에 보인다.

보내지 않는 것. 원본 파일, 파일 이름 · 경로, 위치 정보, 분석 결과(벡터 · 얼굴 정보), 학습, 기기 식별자, 광고 ID.

받는 곳과 길. Anthropic 의 Claude API(api.anthropic.com)로 암호화된 연결(HTTPS)로 바로 보낸다. 개발자의 서버를 거치지 않고, 개발자는 보낸 사진과 답을 보거나 받지 않는다.

받는 것. 사진마다 분류와 확신도, 그리고 답한 모델 이름과 토큰 수. 분류 · 확신도는 기기 안의 학습에, 토큰 수는 사용량 기록에 둔다.

요금. 사용자의 Anthropic 계정에 청구된다. 앱은 월 한도와 추정 비용을 보인다.

Anthropic 의 처리. Anthropic 으로 보낸 정보는 그 API 키의 계정에 적용되는 Anthropic 의 약관과 개인정보처리방침에 따라 처리된다. 보관 기간과 지우는 법도 Anthropic 이 정한다. 개발자는 이것을 정하거나 바꿀 수 없다.

  • 상업 약관(API 에 적용): https://www.anthropic.com/legal/commercial-terms
  • 개인정보처리방침: https://www.anthropic.com/legal/privacy

국외 이전. Claude 를 쓰면 위 정보가 국외의 Anthropic 으로 이전된다.

  • 이전받는 자: Anthropic, PBC(미국).
  • 이전되는 때와 방법: 앱이 요청을 보낼 때마다(사진을 보낼 때 · 키 확인), 암호화된 연결(HTTPS)로 Anthropic 의 서버에 보낸다. 처리되는 곳은 미국이나 Anthropic 이 처리하는 다른 나라이고, Anthropic 이 정한다.
  • 이전되는 항목: 긴 변 512px 이하로 새로 만든 JPEG, 분류 지시문, 자격 증명인 API 키, SDK 의 기술 머리글, 기기의 IP 주소.
  • 이용 목적: 사진의 분류.
  • 보유 · 이용 기간: Anthropic 의 약관과 개인정보처리방침을 따른다.
  • 거부하는 법: Claude 를 켜지 않거나 끈다. 그래도 앱의 다른 기능은 모두 그대로 쓴다.

키 확인. Claude 를 켤 때와 바뀐 안내에 설정에서 다시 동의할 때, 그리고 켜 둔 동안 키를 넣거나 모델을 바꿀 때(키가 있고 지금의 안내에 동의했을 때만) 그 키로 그 모델을 쓸 수 있는지 Anthropic 에 묻는다. 모델 정보만 읽고 사진은 보내지 않는다.

끄면. 이미 보낸 요청은 끊지 않고 답까지 받아, 그 답(분류)과 사용량을 기록한다. 그 뒤로는 아무것도 보내지 않는다 — 꺼져 있는 동안 앱은 네트워크를 전혀 쓰지 않는다.

4. API 키

  • 기기 안에만 둔다. 안드로이드 키스토어의 열쇠(기기 밖으로 꺼낼 수 없다)로 암호화(AES-256-GCM)해 앱 전용 저장공간에 둔다. 설정에 보이는 끝 네 글자만 따로, 암호화하지 않고 둔다.
  • Anthropic 에만, 요청의 자격 증명으로 보낸다. 개발자나 다른 곳으로 보내지 않는다.
  • 설정에는 끝 네 글자만 보인다. 로그 · 학습 파일 · 백업에 넣지 않고, 새 폰으로 옮기는 기기 간 이전에서도 뺀다.
  • 지우기: 설정 → 분류 엔진 · Claude → API 키 → [지우기]. 키 자체는 Anthropic 콘솔에서 폐기할 수 있다.

5. 학습 파일(내보내기 · 가져오기)

  • 설정 → 학습 → [내보내기]를 누를 때만 만든다. 시스템의 파일 선택 창에서 사용자가 고른 곳에 새 파일로 쓴다. 앱은 이 파일을 어디로도 보내지 않는다(사용자가 고른 곳이 클라우드 저장소면 그 저장소의 앱이 올린다).
  • 들어가는 것: 파일 머리(형식 · 판 · 내보낸 때 · 앱 판), 사용자가 바꾼 분류와 Claude 의 답(분류, 출처, 가중치, 확신도, 바꾸기 전 분류와 그 판정을 낸 것(폰 안 모델 · Claude), 사진의 벡터 사본, 벡터를 만든 모델, 답한 모델, 시각), 직접 정한 1등, 묶음에서 뺀 사진 쌍, 1등 일치율의 기록. 사진을 다시 찾는 열쇠로 기기의 미디어 번호(MediaStore ID), 파일 크기 · 해상도 · 촬영 시각, 파일 앞 64KB 의 CRC 가 들어간다.

7. 권한과 쓰임

폴더는 시스템 폴더 선택 창으로 사용자가 고른 곳만 받는다. 사용자가 허용하는 권한(사진 · 동영상 읽기, 고른 사진만 허용, 미디어 관리, 알림)은 모두 건너뛸 수 있다. 나머지는 설치할 때 주어지는 권한이다.

  • 사진 · 동영상 읽기(READ_MEDIA_IMAGES · READ_MEDIA_VIDEO, 안드로이드 12 는 READ_EXTERNAL_STORAGE): 고른 폴더의 목록을 빨리 읽고(조회를 고른 폴더로 좁힌다) 시스템 썸네일을 쓴다. 휴지통 탭만 예외로, 기기 휴지통 전체(다른 앱이 보낸 것 포함)의 사진 · 동영상을 읽어 보인다. 없으면 폴더 선택 창으로 더 느리게 읽고, 휴지통 탭을 볼 수 없다.
  • 고른 사진만 허용(READ_MEDIA_VISUAL_USER_SELECTED, 안드로이드 14 이상): 시스템의 "고른 사진만 허용"을 바르게 받으려고 적는다. 고른 사진만 허용하면 폴더 선택 창으로 읽는다.
  • 미디어 관리(MANAGE_MEDIA, 시스템 설정의 특별한 앱 접근): 휴지통으로 보내기 · 복원 · 영구 삭제 때 시스템 확인창을 매번 띄우지 않는다(영구 삭제는 앱이 먼저 확인을 받는다). 없으면 요청마다 시스템 확인창이 한 번 뜬다.
  • 알림(POST_NOTIFICATIONS): 분석 · 폴더로 정리의 진행과 [멈추기], Claude 분류의 진행(멈추려면 Claude 를 끈다)을 보인다. 없으면 알림 없이 돈다.
  • 인터넷(INTERNET): Claude 기능만 쓴다. Claude 가 꺼져 있으면 쓰지 않는다.
  • 포그라운드 서비스(FOREGROUND_SERVICE · FOREGROUND_SERVICE_DATA_SYNC · FOREGROUND_SERVICE_MEDIA_PROCESSING): 앱이 앞에 있을 때 시작한 긴 일(분석 · Claude 분류 · 폴더로 정리)을 알림을 띄운 채 이어 간다.
  • WAKE_LOCK · ACCESS_NETWORK_STATE · RECEIVE_BOOT_COMPLETED: 작업 예약 라이브러리 WorkManager 가 넣는다. 일하는 동안 기기가 잠들지 않게, Claude 는 연결될 때만 돌게, 재부팅 뒤 예약을 되살리게 한다.
  • com.mergepik.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION: androidx 라이브러리가 넣는 앱 안의 권한이다. 다른 앱이 앱 안의 수신기를 부르지 못하게 한다.

8. 보관과 지우기

  • 기기 안의 정보는 사용자가 지우거나 앱을 지울 때까지 남는다. 다만 다시 만들 수 있거나 오래된 것은 앱이 스스로 치운다.

  • 지우는 법:
    • 학습: 설정 → 학습 → [초기화]를 누르고 확인창에서 확인한다. 사용자가 바꾼 분류, Claude 의 답, 직접 정한 1등, 묶음에서 뺀 쌍, 1등 일치율, Claude 에 다시 보내지 않을 사진 목록을 지운다.

MergePik Privacy Policy

Effective date: October 5, 2026

MergePik (the "app") is an Android app that analyzes the photos and videos in folders you choose, on your device, to group similar shots, sort them into categories and organize them. This policy explains what information the app handles, where it keeps it, and when anything leaves your device.

Summary

  • The developer does not collect your information. There is no developer server, and the app contains no analytics, advertising or crash-reporting SDKs. There are no accounts.
  • Analysis, grouping, classification and learning happen on your device. If you turn on Claude, Claude helps with classification (section 3).
  • Photos leave your device in only one way: after you turn on Claude in Settings, accept the in-app notice and enter your own Anthropic API key, the app sends newly encoded JPEGs, at most 512 px on the long side and without location, device or capture-time metadata, to Anthropic when you ask or as the automatic settings you turned on allow.
  • Claude is off by default. While it is off, the app makes no network connections at all.

1. Information handled on your device

The app keeps the following in its private storage on your device. None of it is sent to the developer.

  • Chosen folders: access to the folders you choose, folder names and paths. Used to reopen your folders.
  • File list: name, extension, subfolder path, size, resolution, capture and modification time, video duration, and the device's media number (MediaStore ID). Used for counts, sizes and the date range on Home, and for sorting. It is matched to the folder whenever the folder is re-read.
  • Analysis results: a numeric vector computed from each photo (image features), sharpness, exposure, composition, pixel hash, face positions, sizes and detection scores, sharpness of the face area, and eyes-open and smile scores. Used for grouping similar shots, picking the best shot and classification.
  • Neighbor lists: one file per folder holding a copy of its analysis results (photo keys, vectors, file size, resolution, capture time and so on) and candidate similar photos. For photos read only through the folder picker, the key includes the document path and name. Used to reopen folders quickly. Not included in backups or device-to-device transfer; the daily cleanup keeps only those of the 5 most recently opened folders.
  • Learning: categories you changed (with a copy of that photo's vector), Claude's answers, best shots you picked, photos you removed from a group, best-shot agreement records. Used to adapt categories and best shots to you.
  • Operation log: items moved to trash, restored, permanently deleted, organized into folders or moved back (including file names and paths) and the results. Used for undo and for cleaning up after an interrupted operation.
  • Claude records: photos waiting to be sent, photos Claude refused or that could not be sent, photos not to send automatically again because you reverted their category, tokens and estimated cost per date, folder and model, and a one-line summary of the response that stopped sending (status, error type, the API's message, request ID). Used for the usage display and monthly limit, and to avoid sending the same photo again automatically.
  • In-progress markers: small files noting which file is being opened, so the app does not keep reopening a file that makes it stop while analyzing or reading file information. The analysis marker holds the key of the file being opened (the device's media number or, for photos read only through the folder picker, its document path and name) with its size and modification time. The file-information marker identifies the file only by a hash (no name or path). They are kept in app-private storage and removed when the work finishes (after a crash, when that work next finishes).
  • Settings: app settings and small values the screens remember (similarity slider step, grid columns, theme and so on).

Faces, location, models and logs are handled as follows.

  • For faces, the app only measures whether a face is present, its position, size and sharpness, and whether the eyes are open and the person is smiling. It does not recognize who anyone is (it does not tell faces apart or match them).
  • The app does not read location (GPS) data from your photos, and it has no location permission.
  • The models used for analysis (TinyCLIP and MediaPipe face models) are bundled with the app and run on your device.
  • The app is built not to write photos, information derived from photos, or your API key to the device logs.

2. Information the developer collects

None. The app sends nothing to the developer.

Google Play may show the developer statistics such as install counts and, where you have allowed it on your device, crash reports, under Google's own policies. This is done by Google Play, not sent separately by the app.

3. Claude (optional) — photos that leave your device

Turning it on. The first time you switch on Settings → Categorization engine · Claude → Use Claude, a notice explains what will be sent, and Claude is turned on only when you tap "Agree and turn on". Once you have agreed, switching it back on does not show the notice again. If an app update changes what the notice means, though, the app shows the same notice once more and asks you to agree again (while Claude is on, when you tap "View" next to "The Claude notice has changed — review and agree" in Settings or tap "Ask Claude"; while it is off, when you switch it back on). Until you agree again, no photos are sent and no key checks are made. Photos waiting to be sent keep waiting and are sent after you agree. Sending also requires your own API key, created in the Anthropic Console.

When photos are sent. When you tap "Ask Claude" or accept the sample card, and according to settings you turn on: when you turn on "Auto-ask for unsure photos" or choose "Claude-first", and when an analysis finishes while either is on. Photos waiting to be sent go out when the connection returns, when a key check succeeds, or after you tap "Retry", change the monthly limit, or an organize-into-folders run ends. Automatic sending also runs while the app is in the background (for example after an analysis with "Analyze only while charging" finishes), and then no notification is shown. A malformed answer is asked once more and a refused batch is asked again one photo at a time, so the same photo can be sent more than once.

Which photos are sent.

  • "Ask Claude": the photos you select, except photos whose category you set yourself and photos not yet analyzed.
  • Sample card: at most 50 photos categorized by the on-device model (unsure photos first).
  • "Claude-first": every photo in the current folder that has neither a category you set yourself nor an answer from Claude (without subfolders when "Include subfolders" is off), and new photos each time an analysis finishes. If more than 200 new photos would be sent, the app first shows the estimated tokens and cost and asks.
  • "Auto-ask for unsure photos": only photos the on-device model categorized and marked unsure. Once it has gone through a folder, it picks only photos analyzed after that (re-analyzed photos included), even if you turn it off and on again, release and re-add the folder, or reset learning.
  • Photos whose category you reverted are not picked automatically (sample card, "Claude-first", "Auto-ask for unsure photos"). Tapping "Allow again" in the photo viewer's Info panel lets that photo (and its copies with the same content) be picked automatically again.

What is sent.

  • A new JPEG made by scaling the photo down to at most 512 px on the long side (smaller photos are not enlarged). The original file is never sent. EXIF and XMP data (location, device, capture time and so on) and any other metadata segments are not included (only a JFIF header and a color profile may remain), and the app checks this again right before sending. For a video, the key frame nearest the middle (the 50% point; a representative frame if the length is unknown) is prepared the same way. A video frame can be enlarged to fit 512 px on the long side.
  • Classification instructions (descriptions of the five categories), photo numbers, the answer format (category keys and confidence) and the chosen model name. For Sonnet 5.5 and Opus 5.5, an effort setting and a setting that lets Anthropic hand a refused request to another Claude model are also sent.
  • Your API key, as the credential for the request, and technical headers sent with every request (including key checks). Added by Anthropic's official SDK: its own User-Agent (SDK name and version), the language (Java), the SDK version, the Kotlin version, the runtime name and version, the operating system name (Android), the operating system version (sent empty: the SDK would put the kernel version string there, which can include the device model and firmware version depending on the manufacturer), the CPU type, the retry count (always 0) and the request and read timeouts. Also the API version and, for Sonnet 5.5 and Opus 5.5, the name of the feature that hands a refused request to another Claude model. Otherwise only standard HTTP headers (accepted format, compression, body length and so on) are sent.
  • As with any internet connection, your device's IP address is visible to Anthropic.

What is not sent. Original files, file names or paths, location data, analysis results (vectors, face information), learning data, device identifiers, advertising ID.

Where and how. Directly to Anthropic's Claude API (api.anthropic.com) over an encrypted connection (HTTPS). Nothing goes through a developer server, and the developer never sees or receives the photos or the answers.

What comes back. A category and a confidence value for each photo, plus the name of the model that answered and token counts. Categories and confidence are stored in the app's learning on your device, and token counts in the usage records.

Cost. Billed to your Anthropic account. The app shows a monthly limit and an estimated cost.

Anthropic's processing. Information sent to Anthropic is processed under the Anthropic terms that apply to the account of your API key and Anthropic's Privacy Policy. Anthropic decides how long it keeps the data and how it can be deleted. The developer cannot set or change this.

  • Commercial Terms (apply to the API): https://www.anthropic.com/legal/commercial-terms
  • Privacy Policy: https://www.anthropic.com/legal/privacy

International transfer. Using Claude transfers the information above to Anthropic, which may be outside your country.

  • Recipient: Anthropic, PBC (United States).
  • When and how: each time the app sends a request (sending photos, key checks), over an encrypted connection (HTTPS) to Anthropic's servers. The data is processed in the United States or wherever else Anthropic processes it; Anthropic decides.
  • Items: the newly made JPEGs (at most 512 px on the long side), the classification instructions, your API key as the credential, the SDK's technical headers, and your device's IP address.
  • Purpose: categorizing your photos.
  • Retention: under Anthropic's terms and privacy policy.
  • How to refuse: do not turn on Claude, or turn it off. Every other feature of the app keeps working.

Key check. When you turn Claude on or agree again to a changed notice in Settings, and when you enter a key or change the model while it is on (only if a key is entered and you have agreed to the current notice), the app asks Anthropic whether the key can use that model. This reads model information only; no photos are sent.

Turning it off. A request already in progress is not cut off: the app receives its answer and records the categories and the usage. Nothing more is sent after that, and while Claude is off, the app makes no network connections at all.

4. API key

  • Kept only on your device, encrypted (AES-256-GCM) with a key held in the Android Keystore (which cannot be exported from the device), in the app's private storage. Only the last four characters shown in Settings are stored separately, unencrypted.
  • Sent only to Anthropic, as the credential for requests. Never sent to the developer or anywhere else.
  • Settings shows only its last four characters. It is not written to logs, learning files or backups, and it is excluded from device-to-device transfer to a new phone.
  • To delete it: Settings → Categorization engine · Claude → API key → Remove. You can also revoke the key in the Anthropic Console.

5. Learning file (export and import)

  • Created only when you tap Settings → Learning → Export, and written as a new file to the location you choose in the system file picker. The app does not send this file anywhere (if you choose a cloud storage location, that storage app uploads it).
  • Contents: a header (format, version, export time, app version); categories you changed and Claude's answers (category, source, weight, confidence, category before your change and what produced it (the on-device model or Claude), a copy of the photo's vector, the model that computed the vector, the model that answered, timestamps); best shots you picked; photos you removed from groups; best-shot agreement records. To find the photos again, it contains the device's media numbers (MediaStore IDs), file size, resolution and capture time, and a CRC of the first 64 KB of each file.
  • Not included: photos, file names or paths (keys of photos read through the folder picker are replaced with random IDs), your API key, the Claude queue, usage and the list of photos not to send again, the operation log, analysis results, settings.
  • The vectors are numbers computed from your photos. They are not the photos themselves, but they are derived from them, and the file also contains capture times and sizes, so we recommend not sharing the file with others.
  • "Import" reads a file you choose and merges it into the learning on your device.

6. Backup and moving to a new phone

  • The app's data is not included in Google cloud backup.
  • Android's device-to-device transfer (moving to a new phone by cable or wirelessly) is not blocked; depending on the transfer tool, the app's data may be copied to the new phone. The API key is excluded, and folder access does not carry over.

7. Permissions and their use

Folders are accessed only when you choose them in the system folder picker. The permissions you grant (Read photos and videos, selected photos access, Media management, Notifications) can all be skipped; the rest are granted at install.

  • Read photos and videos (READ_MEDIA_IMAGES, READ_MEDIA_VIDEO; READ_EXTERNAL_STORAGE on Android 12): listing the chosen folders quickly (queries are limited to those folders) and using system thumbnails. The Trash tab is the exception: it reads the whole device trash, including items other apps moved there, to show its photos and videos. Without it, folders are read through the folder picker, more slowly, and the Trash tab is unavailable.
  • Selected photos access (READ_MEDIA_VISUAL_USER_SELECTED, Android 14 and later): declared so the system's "Allow limited access" choice is handled correctly. With limited access, folders are read through the folder picker.
  • Media management (MANAGE_MEDIA, special app access in system settings): moving to trash, restoring and deleting permanently without a system confirmation every time (the app always asks before deleting permanently). Without it, the system asks for confirmation once per request.
  • Notifications (POST_NOTIFICATIONS): progress with a Pause button for analysis and a Stop button for organizing into folders, and progress for Claude classification (to stop it, turn Claude off). Without it, tasks run without notifications.
  • Internet (INTERNET): the Claude feature only. Not used while Claude is off.
  • Foreground service (FOREGROUND_SERVICE, FOREGROUND_SERVICE_DATA_SYNC, FOREGROUND_SERVICE_MEDIA_PROCESSING): continuing long tasks started while the app is open (analysis, Claude classification, organizing into folders), with a notification shown.
  • WAKE_LOCK, ACCESS_NETWORK_STATE, RECEIVE_BOOT_COMPLETED: added by the WorkManager task-scheduling library, to keep the device awake during a task, run Claude only when connected, and restore scheduled tasks after a restart.
  • com.mergepik.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION: an app-internal permission added by an androidx library, so other apps cannot call the app's internal receivers.

8. Retention and deletion

  • Information on your device stays there until you delete it or uninstall the app, except data the app can rebuild or that has aged out, which it removes by itself.
    • The file list is matched to the folder whenever the folder is re-read (rows of files that are gone are removed). Releasing a folder removes its file list, its photos that were waiting to be sent to Claude, and its neighbor-list file.
    • Once a day, after re-reading folders: analysis results of photos and videos that are no longer on the device (only when full photo and video access is allowed; photos read only through the folder picker count as gone when they are no longer in a chosen folder's list) and refused or failed Claude records of photos confirmed gone through MediaStore (also only with full access; the records of photos read only through the folder picker are kept so that the same photo is not sent again automatically), operation-log entries older than 30 days (unfinished operations, and the records used for undo — the 10 most recent trash operations and the last organize-into-folders run — together with everything after them, are kept), and neighbor-list files of folders other than the 5 most recently opened.
    • Learning (categories you changed, Claude's answers, best shots you picked, photos removed from groups, best-shot agreement records, photos not to send again) and Claude usage records are never removed automatically.
  • The developer keeps nothing.
  • How to delete:
    • Learning: Settings → Learning → Reset, then confirm. Deletes the categories you changed, Claude's answers, best shots you picked, photos removed from groups, best-shot agreement records and the list of photos not to send to Claude again.
    • Per photo: "Revert" in the photo viewer's Info panel removes that photo's category, or the removed-from-group pairs that include it (categories can also be reverted for photos selected in the Categories tab). For a photo whose category you reverted, "Allow again" in the same panel removes that photo (and its copies with the same content) from the list of photos not to send to Claude again.
    • API key: Settings → Categorization engine · Claude → API key → Remove.
    • All app data: in your device settings, App info → MergePik → Storage → Clear data, or uninstall the app.
    • Exported learning files: delete them where you saved them.
    • Information sent to Anthropic: governed by the Anthropic terms and policy in section 3.
  • Uninstalling the app does not delete your photos or videos.

9. Security

  • Communication with Anthropic uses HTTPS only. Release builds do not open unencrypted connections.
  • The API key is encrypted with the Android Keystore.
